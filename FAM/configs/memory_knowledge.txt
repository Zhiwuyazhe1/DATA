参数编码知识(只按照函数声明中的参数进行编码,不管docstring中的参数)：
<-1>表示返回值
<0>表示this指针
<1>, <2>, ... 则是按顺序表示函数参数
比如 “int* test(int *a, double b, int c);” 其中返回值int*为<-1>, 参数a为<1>, 参数b为<2>, 参数c为<3>，由于该函数为非成员函数，所以不需要<0>

内存领域知识：
指令知识：
assign: <x> = <y> : 类似c语言的赋值操作，至多支持一个 ‘||’ 运算符。
malloc(<x>, may) : 标记可能对<x>申请一块内存，只在明确使用new或者malloc指令申请堆内存时使用，容器有自己的堆内存管理，不建模！
free(<x>, must) : 标记一定会释放<x>所申请的内存, 只在明确使用delete或者free指令释放堆内存时使用，容器有自己的堆内存管理，不建模！
overflow(<x>, [<y>, <z>]) : 用于进行迭代器、下标访问、计数访问时，检测是否溢出。将<x>限制在[<y>, <z>]的区间范围内（闭区间）， 要精确计算边界，超出该范围则认为会发生溢出。如果函数中明确提及具有边界检查类似的功能，则不需要使用该指令。
expansion(<x>) : 将<x>标记为可能发生扩容。构造函数不认为会发生扩容！只针对连续存储容器可能发生扩容情况时（插入、赋值、替换等操作）使用，其余情况禁止使用。
swap(<x>, <y>) : 交换<x>和<y>内存信息， 只针对<x>这种参数，不能对<x>.field使用。 只针对swap函数的语义使用。

建模知识：
抽象属性模型：
strlen 表示字符串的有效长度，只有类string类型，如string\stringView\char* 可以使用该属性，并且使用了该属性，也一定要使用size属性，其size一定要通过该属性来表示，比如strlen + 1！
size 表示容器的大小，数组的大小等,这是一种抽象。如果容器使用了strlen属性，那么其size一定要由自身的strlen + 1 来计算，保证摘要的一致性！
begin 表示起始迭代器, 专用于容器
end 表示结尾迭代器，专用于容器
field：对数组、指针以及类或结构体成员的抽象建模,对于字符串，表示字符串内容;
对于数组而言， int a[]， a.field 可以指代a[0]，也就是只保留一个元素的索引敏感
对于指针而言， int *a, a.field 可以指代*a， 也就是a指向的内存区域
对于对象而言， class a, a.field 可以指代a所有的域

常量模型：
MAX 表示最大值
MIN 表示最小值
NULL 对于指针而言表示空指针，对于其他类型表示类似析构或者清除的语义。构造函数或者类似pop的语义无需使用该常量赋值
NPOS 表示c++标准中npos的语义

返回值模型：
如果为函数声明void，则不需要为返回值赋值
如果存在多条路径，将其合并为一条路径，副作用进行合并，在返回值中可以用||的形式表达不同路径的返回值(但||只能使用一次)

容器建模：
对于添加、替换和赋初值的语义，只按照 <x>.field = <y> 这种形式建模，不考虑原来的取值；以first, last这种迭代器形式添加元素： 只保留first指向的元素，即<x>.field = <first>.field
对于删除元素的语义，只按照<x>.size = <x>.size - 1 这种形式建模，不对field进行修改
对于清空元素的语义，按照<x>.field = NULL, <x>.size = 0（根据实际大小情况考虑） 的方式建模
对于析构的语义，按照 <x> = NULL 的方式建模

范围约束（overflow）：
尤其对于pos，count的类似参数，需要注意是否添加范围约束，同时要注意精确计算左右边界，都是闭区间
指针的范围一般可以表示为[<x>.value, <x>.value + <x>.size - 1]
下标的范围一般可以表示为[0, <x>.size - 1],如果有strlen类型，优先使用strlen表示， 也就是[0, <x>.strlen]；
文档中如果描述了 类似“如果请求的子串越过字符串的结尾，即 count 大于 size() - pos（例如 count == npos），那么返回的子串是 [pos, size())”，则无需对count进行约束

顺序性：
对于存在数据依赖的情况，要考虑副作用的先后，比如先对<0>赋值，然后再用<0>对<-1>赋值，这和先用<0>对<-1>赋值再对<0>赋值是不一样的。

运算约束：
运算的复杂度不能超出3个Key,否则应该放弃精确建模
如果无法精确建模，则尝试构建出其最小值和最大值，用范围进行粗略建模，但要注意边界值是否可以取到
禁止运算表达式中出现括号！​
运算仅限于grammar中的+,-,*,/，不允许其他运算符
如果参数为迭代器，我们禁止两个迭代器之间的运算！迭代器只考虑模糊建模，不考虑精确建模。

注意事项：
如果容器只是内部顺序发生了变化，则不进行副作用的建模， 像swap(<0>.field, <0>.field) 这种用法既不符合语法，也没有意义。
如果发现无法建模某些副作用，则先考虑能否模糊建模，比如返回值可以确定在某个范围，如果不可以，则放弃建模。
对于参数中的右值引用，我们当作左值引用处理，不考虑move类似的操作带来的副作用。
不用考虑allocator这种内存分配器的副作用。
最后，再去检查生成的摘要是否需要进行overflow的判断，如果需要，再检查边界是否精确.
